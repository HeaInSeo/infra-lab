큐 사건 동기화 계약 QSYNC-20261010-v1 — 사용자2026-10-10 반복 불일치 해결 승인
이 절은 기존 작업 범위·권한·WIP·사용량·HOLD를 바꾸지 않는 기록/인수 계약이다.
1. 권위 분리: Router는 현재 제품 scope/HOLD/allowlist의 권위이고, 실행 상태는 지정 original/paired 행의 실제 own CLAIM/CHECKPOINT/RELEASE가 권위다. 역할 큐·Router·허브·대시보드의 복사한 ACTIVE/WAIT/미인수는 마지막 관측일 뿐이다. CURRENT 제목·본문 첫 블록·Notion 편집시각·과거 속성 중 하나만으로 실행 상태나 인수 부재를 판정하지 않는다.
2. 인수 직전과 RELEASE 직후 지정 original + paired + 직접 successor를 fresh fetch한다. 완전히 같은 session/task/phase의 최신 유효 event와 version을 전체 관련 receipt에서 찾고, 더 뒤 RELEASE가 있으면 앞 CLAIM/lease/LIVE는 닫힌 이력이다. terminal RELEASE 이후 새 유효 own CLAIM이 없으면 ACTIVE0다. 캐시한 lease/READY0을 재사용하거나 다른 task/phase event를 섞지 않는다. 입력이 바뀌면 그 영향을 다시 판정하며 변화 없는 head를 재검토하지 않는다.
3. 자기 event 기록은 원본 본문과 기존 속성을 한 묶음으로 갱신한다. 본문에 QUEUE_EVENT_V1 JSON code block을 두며 event_id, task_id, phase, role, session_id, version, kind(CLAIM/CHECKPOINT/RELEASE), event_at_utc, repo_pr, head_or_digest, lease_state, next_owner를 실제 관측값으로 기록한다. RELEASE의 lease_state=RELEASED다. 단일 현재 event block을 갱신하고 이전 own proof는 보존한다. 실제 시계 읽기·자기 version 증가·정확한 scope가 선행한다. 기존 이벤트 ID/내용 요약/실제 확인/작업 상태/다음 담당자/큐 구획과 자기 소유 session·체크포인트·Authority 필드를 동일 event에 맞춘다. 다른 worker의 proof나 중앙 proof를 만들지 않는다.
4. 내용/속성 업데이트와 async 성공 뒤 원본을 재조회해 event_id/version/kind/head/next_owner가 같은지 확인한다. 이 기록은 원자적 CAS가 아니다. 더 새 다른 own event/claim이면 덮어쓰지 말고 재계산한다. 부분 실패는 RECORD_SYNC_PENDING이며 성공한 자기 event를 되돌리지 않는다. 그 영향을 받는 인수 판단만 UNKNOWN으로 두고 같은 실행에서 한정 재시도/정확한 오류를 기록한다. 본문·속성이 일치하지 않은 채 전체 인계 완료/NO ELIGIBLE WORK를 보고하지 않는다.
5. 중앙 전용 필드·역할 큐/Router/허브/대시보드는 중앙만 쓴다. worker는 자기 원본/기존 실행 receipt만 기록하고 source_event_id/version/시각과 CENTRAL_SYNC_PENDING을 전달한다. 중앙은 worker event/session/lease/checkpoint/LIVE/Authority를 편집하지 않는다. 자기 신규 claim/release와 충돌하는 중앙 instruction이 있으면 actual source와 scope를 대조하고 원본 proof를 보존한다.
6. 정상 run 종료 직전 fresh source를 다시 읽는다. 자기 RELEASE, 새 상대 RELEASE 또는 bounded same-original finding이 도착했으면 실제 native 선행·authority·slot 안에서 기존 후속 인수를 재판정한다. 같은 role이 아닌 중앙 acceptance/dispatch가 남으면 CENTRAL_ACTION_PENDING + owner + source event + 정확한 next action을 기록한다. 새 blocking finding은 해당 scope의 correction으로 연결하고 사용자 gate/전역 HOLD로 확대하지 않는다. 빈 역할 요약이나 Notion SQL quota 때문에 기존 알려진 original/paired를 생략하지 않는다.
7. 계약 사용 근거는 다음 기존 scheduled receipt에 QSYNC-20261010-v1과 사용한 original source event를 기록한다. readback 성공은 기록 일치일 뿐 제품/독립 PASS가 아니다. trigger_kind는 실제 시작 경로를 사용하고 기존 MANUAL_EXISTING_SERVICE를 SCHEDULED로 오표기하지 않는다. 새 timer/worker/도구 권한은 만들지 않는다.
